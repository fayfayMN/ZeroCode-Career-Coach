# Skill: Technical Interview Preparation

Prepare the candidate for the technical portions implied by the JD (the role's stack and level),
not a generic CS quiz.

## Map prep to the role
- Read the JD's stack and responsibilities. Derive the **technical topics** most likely to be
  tested (e.g. for a backend role: data modeling, API design, concurrency, system design at the
  stated scale; for data: SQL, pipelines, ML fundamentals; for frontend: rendering, state, perf).
- Calibrate depth to **level** (intern/new-grad → fundamentals + a couple of DS&A; senior →
  system design, trade-offs, leadership-through-technical-decisions).

## Provide
- A focused list of **technical topics** to review, ordered by likelihood.
- A few **sample problems / questions** representative of the role and level, each with a short
  note on what a strong answer demonstrates (approach, trade-offs, communication).
- For coding rounds: remind them to **think aloud, clarify requirements, state complexity, test
  edge cases** — interviewers score process, not just the final answer.
- For system design: **requirements → high-level design → deep-dive → bottlenecks/trade-offs.**

## Honesty
Base topics on the JD and the candidate's resume. Flag areas where the candidate looks light so
they can study, rather than pretending they're ready.
